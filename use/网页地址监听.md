# 网页/地址监听（RSS / Atom / JSON）

「网页/地址」来源定时拉取一个**公开地址**（RSS、Atom 或 JSON），把**新条目**变成工单。它适合监听公告、博客、Release Notes、状态页或任何会更新 JSON 列表的接口。

> **它是只读来源：不回帖、不 @。** 条目没有回复通道，工单结果只在面板与工单历史里看；来源也没有策略表单（没有 allowed 名单与准入表）。需要建单时，按下文「让条目建单」用管理 API 给这个实例保存 allowed 名单。

在面板里的位置：**设置 → 工单源 → 网页/地址**（来源项顺序第 3 个）。每个账号是一个独立实例，健康条目名就是实例 id（如 `web:news`）。

## 一、RSS / Atom 示例：监听一个博客或 Release 页

假设要监听 `https://example.com/blog/feed.xml`（RSS 2.0，条目里有 `title`、`link`、`guid`、`pubDate`、`description`）。

1. 设置 → 工单源 → **网页/地址** → **添加账号**，按下表填：

   | 字段 | 值 | 说明 |
   |---|---|---|
   | 账号名（key） | `news` | 实例 id 会变成 `web:news` |
   | 显示名（label） | `公告` | 可选 |
   | 地址 `url` | `https://example.com/blog/feed.xml` | **必须**是 http/https、无用户名密码、非内网地址 |
   | 格式 `format` | 自动识别（`auto`） | 也可强制 `rss` / `atom` / `json` |
   | 首次拉取 `baseline` | 只记录当前条目（`latest`） | 刚添加时已有的文章不会建单，只有之后的新文章会 |
   | 轮询间隔 `pollSeconds` | `300` | 默认 5 分钟，最小 30 秒 |
   | 每轮最多新条目 `maxItemsPerPoll` | `10` | 超出部分留到下一轮，健康详情会写「N more wait for the next round」 |
   | 汇报人 `operator` | 默认 `web` | 条目的汇报人与归属；留空用本机用户名 |

2. 保存后看健康：`ready` 且详情类似 `12 items, 0 new, 12 skipped; baseline recorded the current items` 即第一次轮询成功、已记录当前 12 条、没有建单。
3. 之后博客发文，下一轮健康变成 `13 items, 1 new, 12 skipped`，面板「工单源」里出现一条新工单，Thread 形如 `web:news:https://example.com/blog/post-9`（itemId 取 guid；没有 guid 时取 link）。

**Atom** 同样支持：条目读 `entry` 的 `id`、`title`、`link[href]`（优先 `rel="alternate"`）、`updated`、`summary`，`format` 保持 `auto` 即可。

## 二、JSON 示例：监听一个接口里的列表

假设接口 `https://status.example.com/api/incidents` 返回：

```json
{
  "data": {
    "incidents": [
      { "code": "INC-9", "name": "数据库延迟", "page": "https://status.example.com/incidents/9",
        "detail": "主从延迟 30s", "opened_at": "2026-11-26T08:00:00Z" },
      { "code": "INC-8", "name": "登录失败", "page": "https://status.example.com/incidents/8",
        "detail": "已恢复" }
    ]
  }
}
```

填法（账号名 `status`）：

| 字段 | 值 |
|---|---|
| 地址 `url` | `https://status.example.com/api/incidents` |
| 格式 `format` | `json`（或保持 `auto`，`application/json` 会自动识别） |
| JSON 条目数组路径 `jsonItemsPath` | `data.incidents`（点路径；根就是数组时留空） |
| JSON 条目 id 路径 `jsonIdPath` | `code` |
| JSON 标题路径 `jsonTitlePath` | `name` |
| JSON 链接路径 `jsonLinkPath` | `page` |
| JSON 摘要路径 `jsonSummaryPath` | `detail` |

其余字段同上面的 RSS 示例。生成工单的 Trigger 文本是「标题 + 链接 + 摘要」，Thread 为 `web:status:INC-9`，`meta` 带 `itemId`、`link`、`title`、`publishedAt`。

**缺 id 时的顺序**：`id` → 链接 → 「标题 + 摘要」的哈希。所以接口即使不返回 id 也能去重；但如果标题/摘要会变（例如带时间戳），用稳定的 id 字段最可靠。

## 三、让条目建单（只读来源的准入）

「网页/地址」没有策略表单，因此默认安装策略不会把无来源允许名单的条目放行（工单源里会显示为 filtered / `not_a_member`）。要建单，用管理 API 给该实例保存一份 `policy:<实例 id>`，把 `operator` 写进 `allowed`：

```powershell
$api = 'http://127.0.0.1:3082/orchestrator/api'
$headers = @{ 'x-orchestrator-request' = '1' }
$rev = (Invoke-RestMethod "$api/settings" -Headers $headers).sources |
  Where-Object { $_.id -eq 'web:news' } | ForEach-Object { $_.policy.revision }
$body = @{ value = @{ allowed = @(@{ id = 'alice' }); admission = @{} }; revision = $rev } | ConvertTo-Json -Depth 5
Invoke-RestMethod -Method Put -Uri "$api/settings/policy:web:news" -Headers $headers `
  -ContentType 'application/json' -Body $body
```

- `allowed` 里的 id 就是实例的 `operator`（多个实例各自保存各自的名单）。
- 之后的条目以「允许发送人的直接请求」进入评估：`eval.mode` 为 `off` 时仍会走准入表；`observe` / `auto` 下才会进入评估并可能建单。
- 修改 `operator` 后要同步改这份 allowed 名单。

## 四、首次拉取（baseline）与去重

- **`latest`（默认）**：第一次轮询只把当前条目的 id 记下来（KV `web-seen:<实例>` + `web-initialized:<实例>`），一条也不建单。适合「从今天开始的新消息」。
- **`all`**：第一次就把当前所有条目建单（受 `maxItemsPerPoll` 限制，其余下一轮继续）。适合「把历史积压也处理掉」，注意会一次生成较多工单。
- 已建单的条目 id 记 7 天、最多 1000 个；同一 id 不会重复建单。即使 seen 记录丢失，重复的 Trigger id 也会被引擎判为 duplicate。
- 失败的一轮不写 seen；下一轮重试，不会产生第二张工单。

## 五、安全限制（SSRF 防护）

本来源只允许抓取公网地址，保存时和每次请求（含每一跳重定向）都会检查：

- 只允许 **http / https**；`file:`、`ftp:` 等一律拒绝，绝不读取本地文件。
- 地址里**不能带用户名/密码**。
- 拒绝 `localhost`、`*.localhost`、`*.local`、回环、内网、链路本地与 IPv6 唯一本地地址：`127.0.0.0/8`、`10/8`、`172.16/12`、`192.168/16`、`169.254/16`、`::1`、`fc00::/7`、`fe80::/10`。
- 域名会经 DNS 解析，**解析出的所有地址**都必须是公网地址才会发请求。
- 重定向最多 3 跳，**每一跳都重新校验**；公网地址无法把请求重定向进内网。
- 单次请求 20 秒超时；响应正文最多读 2 MiB；User-Agent 固定为 `dsh-superagent/web`。

## 六、常见问题

| 健康 / 报错 | 原因 | 处理 |
|---|---|---|
| `The web address is not configured: url` | 还没填地址（paused） | 在实例设置里填 `url` |
| 保存时报 `must be an absolute http or https address` | 地址相对路径或协议不对 | 填完整的 `https://…` 地址 |
| 保存时报 `must not name a local or private address` | 地址是 localhost/内网 IP/`.local` | 换公网地址（或用公网隧道） |
| `resolves to …, a local or private address` | 域名当前解析到内网 | 换解析到公网地址的域名 |
| `answered HTTP 404` / `HTTP 500` | 地址不可用 | 浏览器里先确认地址可访问 |
| `timed out after 20 s` | 地址超时 | 检查网络与地址延迟 |
| `is larger than 2097152 bytes` | 响应超过 2 MiB | 改用分页/精简的订阅地址 |
| `is neither an RSS/Atom feed nor a JSON document` | `auto` 无法识别 | 明确设置 `format`，或换正确地址 |
| 健康 `ready` 但工单源里 filtered / `not_a_member` | 没给实例保存 allowed 名单 | 按第三节用 API 保存 `policy:web:<key>` |
| 条目一直不建单 | `baseline=latest` 只记录旧条目 | 只有**添加之后的新条目**会建单；需要历史积压改用 `all` |
