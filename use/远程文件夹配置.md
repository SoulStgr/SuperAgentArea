# 远程文件夹配置（SSH/SFTP）

「远程文件夹」来源通过 **SFTP over SSH** 监听另一台机器上的收件目录：远端 inbox 里出现文件 → 建工单 → 产物回执写入远端 outbox → 原文件移到 `.done/`。

> **安全前提：只支持密钥登录，不支持密码。** 密码无法在不落盘明文、不依赖额外工具的前提下安全地非交互使用；SSH 密钥 + 强校验 known_hosts 是这类常驻监听的标准做法。

## 你现在只有 地址 + 用户名 + 密码，怎么办？

把密码换成一次性配置的密钥（之后不用再输密码），大约 5 分钟：

### 1. 在本机生成专用密钥

```powershell
ssh-keygen -t ed25519 -f "$env:USERPROFILE\.ssh\saa_remote" -N '""'
```

生成两个文件：`saa_remote`（私钥，**不要外传**）与 `saa_remote.pub`（公钥）。

### 2. 把公钥装到远程账号（需要一次密码）

```powershell
$pub = Get-Content "$env:USERPROFILE\.ssh\saa_remote.pub" -Raw
$pub | ssh 用户名@远程地址 "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"
```

这一条会提示输入一次密码；成功后远程账号就信任这把密钥了。建议给这把 key 加限制（可选）：

```
# ~/.ssh/authorized_keys 中该行前面加：
command="internal-sftp -d /srv/saa",no-pty,no-agent-forwarding,no-port-forwarding ssh-ed25519 AAAA...
```

### 3. 记录远程主机指纹（known_hosts）

```powershell
ssh-keyscan -p 22 远程地址 > "$env:USERPROFILE\.ssh\saa_known_hosts"
ssh-keygen -lf "$env:USERPROFILE\.ssh\saa_known_hosts"   # 记下 SHA256 指纹，和远端管理员核对
```

**不要**用 `StrictHostKeyChecking=no` 或 `accept-new` 跳过校验；本来源会拒绝这种配置。

### 4. 准备远端目录（绝对路径）

```sh
# 在远程机器上
mkdir -p /srv/saa/inbox /srv/saa/outbox
chmod 700 /srv/saa/inbox /srv/saa/outbox
```

### 5. 在面板里添加账号

设置 → 工单源 → **远程文件夹** → 添加账号：

| 字段 | 填什么 |
|---|---|
| host | 远程地址（域名或 IP） |
| port | 22（或你的 SSH 端口） |
| username | 远程用户名 |
| identityFile | 本机私钥绝对路径，如 `C:\Users\你\.ssh\saa_remote` |
| knownHosts | 本机 known_hosts 绝对路径，如 `C:\Users\你\.ssh\saa_known_hosts` |
| hostKeySha256 | 可选，填 `SHA256:...` 指纹做二次钉死 |
| inbox / outbox | 远端**绝对路径**，如 `/srv/saa/inbox`、`/srv/saa/outbox` |
| operator | 投件归属的操作者 id（用于策略 allowed，一般填你的用户名） |
| pollSeconds | 轮询间隔，默认 30 秒 |
| maxFileBytes | 单文件上限，默认 1 MiB（可调大到 16 MiB） |

保存后看实例健康：`ready` 即已连上；`paused` 会写明缺哪个字段；`error` 会写连接/权限/主机密钥原因。

## 投件与回执

- 往远端 `inbox` 放一个 `.md`/`.txt`/任意文本文件 → 下一轮轮询建工单。
- 工单 Trigger 文本就是文件内容（截断 8000 字），汇报人=operator。
- `ready` 后，回执写到 `outbox/<messageId>.md`；源文件移入 `inbox/.done/`。
- 同文件不会重复建单（KV 去重），失败保留源文件下轮重试。

## 常见错误

| 健康详情 | 原因 | 处理 |
|---|---|---|
| `Host key verification failed` | knownHosts 缺失/不匹配 | 重新 `ssh-keyscan` 并核对指纹 |
| `Permission denied (publickey)` | 公钥没装对/私钥不对 | 检查 `authorized_keys` 与 identityFile |
| `invalid remote path` | 路径不是绝对路径/含非法字符 | 只用 `/` 开头的 `[A-Za-z0-9._/-]` |
| `remote inbox is missing` | 远端目录不存在 | 在远端 `mkdir -p` |
| `file exceeds maxFileBytes` | 单文件超限 | 调大配置或拆分文件 |

## 为什么不做密码登录

- Windows OpenSSH 的 `sftp` 没有内建的非交互密码参数；要支持密码就得引入额外依赖（如 `ssh2`）并把密码存进配置/状态库。
- 常驻监听意味着密码会长期可用；密钥可以单独吊销、加 `command=`/`from=` 限制，泄露面更小。
- 如果确实只能用密码，建议让远端管理员给你一把受限密钥，而不是把密码交给插件。
