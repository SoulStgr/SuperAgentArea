# 远程文件夹配置（SSH/SFTP）——照着做就行

「远程文件夹」让 SuperAgentArea 监听**另一台机器**上的一个文件夹：那边放进一个文件，这边就建一张工单；干完活，回执写回那边的另一个文件夹。

**先说明一件事：这个功能只用 SSH 密钥登录，不用密码。** 这不是偷懒，而是安全考虑：

- 密码要长期保存才能自动轮询，等于把服务器密码放在本机；
- 密钥可以单独吊销、可以限制来源 IP、可以限制只能传文件；
- 密钥登录是服务器自动任务的常规做法。

**你现在只有「地址 + 用户名 + 密码」也没关系**：下面第 1～3 步花 5 分钟，把密码换成一把专用密钥，之后就不用再输密码了。

---

## 整体流程图

```
你的电脑                                  远程服务器
┌─────────────────────────┐              ┌──────────────────────────┐
│ SuperAgentArea 面板      │              │  /srv/saa/inbox   （收件）│
│  ├ 私钥 saa_remote       │  SSH/SFTP    │  /srv/saa/outbox  （回执）│
│  ├ known_hosts           │ ──────────▶  │  /srv/saa/inbox/.done     │
│  └ 每 30 秒看一次 inbox  │              │                          │
└─────────────────────────┘              └──────────────────────────┘

有人往 inbox 放文件 → 建工单 → 干完 → 回执写进 outbox → 原文件移到 .done
```

---

## 第 1 步：在本机生成一把专用钥匙

打开 PowerShell（不用管理员），执行：

```powershell
ssh-keygen -t ed25519 -f "$env:USERPROFILE\.ssh\saa_remote" -N '""'
```

会得到两个文件：

| 文件 | 是什么 | 怎么处理 |
|---|---|---|
| `C:\Users\你\.ssh\saa_remote` | **私钥**（相当于钥匙） | 留在本机，不要发给任何人 |
| `C:\Users\你\.ssh\saa_remote.pub` | **公钥**（相当于锁） | 装到远程服务器上 |

> 如果提示 `ssh-keygen 不是内部或外部命令`：说明本机没装 OpenSSH 客户端。Windows 10/11 可在「设置 → 应用 → 可选功能 → 添加功能 → OpenSSH 客户端」安装。

---

## 第 2 步：把公钥装到远程服务器（只输一次密码）

```powershell
$pub = Get-Content "$env:USERPROFILE\.ssh\saa_remote.pub" -Raw
$pub | ssh 用户名@远程地址 "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"
```

把 `用户名`、`远程地址` 换成你的。执行后会提示输入**一次**密码；看到命令正常结束就成功了。

验证一下（这次应该不再问密码）：

```powershell
ssh -i "$env:USERPROFILE\.ssh\saa_remote" 用户名@远程地址 "echo 连接成功"
```

> 如果仍然问密码：检查远程 `~/.ssh/authorized_keys` 里是否有以 `ssh-ed25519` 开头的一行；检查 `~/.ssh` 权限是否为 700、`authorized_keys` 是否为 600。

---

## 第 3 步：记录服务器指纹（防冒充）

```powershell
ssh-keyscan -p 22 远程地址 > "$env:USERPROFILE\.ssh\saa_known_hosts"
ssh-keygen -lf "$env:USERPROFILE\.ssh\saa_known_hosts"
```

把输出的 `SHA256:...` 指纹**通过另一个渠道**（问管理员、看服务器控制台）核对一次。核对一致才继续。

> 不要用 `StrictHostKeyChecking=no` 或 `accept-new` 跳过校验；本功能会拒绝这种配置。这一步是防止有人冒充你的服务器。

---

## 第 4 步：在远程服务器建两个目录

登录服务器（或用你的运维工具）执行：

```sh
mkdir -p /srv/saa/inbox /srv/saa/outbox
chmod 700 /srv/saa/inbox /srv/saa/outbox
```

记住这两个**绝对路径**，下一步要填。目录名可以换，但必须是 `/` 开头的绝对路径。

---

## 第 5 步：在面板里添加账号

打开 **设置 → 工单源 → 远程文件夹 → 添加账号**，按下表填：

| 面板字段 | 填什么 | 例子 |
|---|---|---|
| host | 服务器地址 | `192.168.1.20` 或 `saa.example.com` |
| port | SSH 端口，默认 22 | `22` |
| username | 登录用户名 | `saa` |
| identityFile | 本机**私钥**的完整路径 | `C:\Users\你\.ssh\saa_remote` |
| knownHosts | 本机 known_hosts 的完整路径 | `C:\Users\你\.ssh\saa_known_hosts` |
| hostKeySha256 | 可选，再钉死一次指纹 | `SHA256:xxxxx` |
| inbox | 远程**收件**目录，绝对路径 | `/srv/saa/inbox` |
| outbox | 远程**回执**目录，绝对路径 | `/srv/saa/outbox` |
| operator | 这次投件算谁发起的 | 你的用户名，如 `zhangsan` |
| pollSeconds | 多久看一次，默认 30 秒 | `30` |
| maxFileBytes | 单个文件上限，默认 1 MiB | `1048576` |

保存后看这张卡片的**健康状态**：

- `ready` → 已经连上，开始监听；
- `paused` → 会写缺哪个字段；
- `error` → 会写具体原因（主机指纹不对、权限不对、目录不存在等）。

---

## 第 6 步：试一次

在远程服务器上放一个文件：

```sh
echo "帮我看一下这个需求" > /srv/saa/inbox/hello.md
```

等一个轮询周期（默认 30 秒），面板的工单源/工作站里就会出现工单；工单完成后，回执会出现在 `/srv/saa/outbox/<工单id>.md`，原文件被移到 `/srv/saa/inbox/.done/hello.md`。

## 安全建议（建议逐条做）

1. **一把钥匙只干一件事**：`saa_remote` 只给这个插件用，不复用你平时登录的钥匙。
2. **限制这把钥匙的权限**：在远程 `~/.ssh/authorized_keys` 里，把这一行改成：

   ```
   from="你的公网IP",no-pty,no-agent-forwarding,no-port-forwarding,command="internal-sftp -d /srv/saa" ssh-ed25519 AAAA...（你的公钥）
   ```

   这样即使私钥泄露，也只能传文件、只能进 `/srv/saa`。
3. **用专用账号**：远程建一个 `saa` 账号，只给它 `/srv/saa` 的读写权限，不要用 root。
4. **核对指纹**：known_hosts 的指纹一定通过第二个渠道核对，别直接相信第一次连接。
5. **可选再钉死指纹**：面板 `hostKeySha256` 填 `SHA256:...`，服务器换钥匙会直接报错，而不是静默连上。
6. **定期轮换**：换钥匙时先加新公钥、确认能用，再从 `authorized_keys` 删旧公钥。
7. **不要在远端放敏感文件**：这个目录是给任务投件用的，权限 700，别放密钥/密码。

## 常见问题

| 面板健康提示 | 可能原因 | 怎么办 |
|---|---|---|
| `Host key verification failed` | knownHosts 缺失或服务器换过钥匙 | 重新 `ssh-keyscan`，核对指纹；不要跳过校验 |
| `Permission denied (publickey)` | 公钥没装对 / 私钥路径错 | 用第 2 步的命令重装公钥；确认 identityFile 指向私钥而不是 `.pub` |
| `invalid remote path` | 路径不是绝对路径或含空格/特殊字符 | 只用 `/` 开头的字母数字、`.`、`_`、`-`、`/` |
| `remote inbox is missing` | 远端目录没建 | 回第 4 步 `mkdir -p` |
| `file exceeds maxFileBytes` | 文件超过上限 | 调大 `maxFileBytes`（最大 16 MiB）或拆文件 |
| 一直 `paused` | 字段没填全 | 看健康详情里列出的缺项 |

## 为什么不做密码登录（再强调一次）

- Windows 自带的 `sftp` 没有安全的“非交互密码”参数；要支持密码就得引入额外组件，并把密码长期存下来。
- 常驻监听 = 密码长期有效；密钥可以随时吊销、限制来源和命令。
- 如果服务器只允许密码，建议让管理员给你建一个**专用账号 + 专用密钥**，而不是把密码交给插件。

> 一句话：**用密钥，限制权限，核对指纹**。这三件事做到，远程文件夹就是安全的。
