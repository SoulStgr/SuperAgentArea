## 1. 后端

### 1.1 视图（`src/app/views/projects.ts` 新增）

**列表**（`GET /projects?status=active|archived`）每项：

| 字段 | 说明 |
|---|---|
| `id/key/name/kind/location` | Project 记录；`location.type` 展示地址类型（managed/folder/repo） |
| `openTickets/tickets` | 该项目未结束 / 全部工单数（`ticket.projectId`） |
| `artifacts` | 产物数（`artifact.project`） |
| `sources` | 关联来源（`sourceIds` 解析为实例标题；空则取该项目工单的 `sourceId` 去重） |
| `lastActivity` | 该项目最近工单/产物的时间 |
| `reporter` | 最近工单的汇报人（可选） |
| `archivedAt` | 归档时间 |

排序：**workspace 固定第一**，其余按 `updatedAt` 倒序；默认只列 active，`status=archived` 列归档。

**详情**（`GET /projects/:id`）：`{ project, counts{openTickets,tickets,threads,decisions,artifacts}, sources[], tickets(首页), threads(首页), decisions(首页), artifacts(摘要首页), recentTriggers[] }`

- **项目 → 线程**：该项目工单的 origin threads + follows；加上 `KV.projects.answers` 记录到该项目的线程。
- **项目 → 决定**：上述线程的 decisions（时间倒序）。
- **项目 → 产物**：`artifact.project = id`（P5 再做下载/反查）。
- 分页端点（复用现有视图函数并加 project 过滤）：
  - `GET /projects/:id/tickets?state=&offset=&limit=`
  - `GET /projects/:id/threads?filter=&offset=&limit=`
  - `GET /projects/:id/decisions?offset=&limit=`

### 1.2 写操作

- `POST /projects` `{ name, location, kind? }`：面板来源（`specifiedBy/confirmedBy = PANEL_PERSON`）；校验名称非空、唯一 key、地址合法（复用 `ProjectService.create` 的校验：绝对路径/可创建/可写/非系统目录；仓库协议）；返回新项目。
- `PATCH /projects/:id` `{ name?, aliases?, archived?, sourceIds? }`：
  - 改名：更新 `value.name`（key 不变）；
  - 归档/恢复：`status` + `archivedAt`；归档后列表默认不显示；
  - `aliases`：字符串数组去重；
  - `sourceIds`：只能引用已存在实例；未知实例 4xx。
  - **目录不可改**（outputDir/scratchDir 建站时确定；改动涉及历史产物，留 P6）。
- 错误码：`projectExists`（key 冲突）、`projectLocationInvalid`、`unknownProject`、`unknownSource`。

### 1.3 测试

- `views.spec`/`runtime.spec`：项目列表（workspace 第一、active/archived 过滤）、计数（工单/线程/决定/产物）、sourceIds 解析、最近活动、归档恢复、改名/别名、非法 sourceIds。
- `http.spec`：GET/POST/PATCH 路由与错误码。
- 旧数据：无项目的历史工单仍归 workspace（已有），列表里 workspace 计数正确。

## 2. 前端（工作站页）

### 2.1 路由与导航

- `TABS` 增加 `workstations`（标签「工作站 / Workstations」），位置在「工单源」之后；`{page:'workstations'}` 列表、`{page:'workstations', id}` 详情、`query.segment` 指定六段之一（来源/触发/评估/执行/设置/agent）。
- 保持现有自研路由（深链不做）。

### 2.2 列表页

- 卡片网格：名称、状态（active/archived）、地址类型标签（托管/文件夹/仓库）、关联来源数、未结束工单数、产物数、最近活动、最近汇报人。
- `workspace` 卡固定首位，标「固化」，不可归档/删除。
- 卡内六段按钮：`来源 触发 评估 执行 设置 agent` → 进入详情对应段（`query.segment`）。
- 页头动作：**新建工作站**、**显示/隐藏已归档**。
- 空态：只有 workspace 时提示「还没有工作站，从工单源投件或新建一个」。

### 2.3 新建工作站对话框

- 名称 + 地址类型（托管 / 本地文件夹 / 仓库：本地路径或远程 URL + 可选分支）；提交 `POST /projects`；错误就地显示（名称冲突/路径非法）。
- 说明：外部地址只能由人指定（面板操作），与 P2 的安全口径一致。

### 2.4 详情页（页内分段，不叠 Tab）

| 段 | 内容 |
|---|---|
| 来源 | 关联实例列表（标题/状态/最近投件）+ 跳到工单源详情；可勾选关联/解除（PATCH sourceIds） |
| 触发 | 该项目线程（复用线程行），点击进线程页 |
| 评估 | 该项目决定（复用决定行），显示强度/原因/策略版本（P2 数据已就绪） |
| 执行 | 该项目工单（复用 TicketLine，分页），点击进工单页 |
| 设置 | 名称/别名编辑、目录（outputDir/scratchDir/rulesDir，只读展示）、归档/恢复 |
| agent | **占位**：按钮禁用 + 说明「项目会话将在 P6 提供」（不假装可用） |

- 顶部：名称、地址、状态、归档/恢复按钮、返回。
- 计数徽标与分段标签一致（工单数=执行段列表总数；产物数留 P5 链接）。
