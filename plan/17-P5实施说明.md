## 1. 后端

### 1.1 视图（`src/app/views/artifacts.ts` 新增）

**列表行**（`GET /artifacts?q=&project=&source=&ticket=&offset=&limit=`）：

| 字段 | 说明 |
|---|---|
| `id` | artifact 行 id |
| `name` | `deliver/` 相对名（正斜杠） |
| `ticket`/`ticketTitle` | 工单 id 与标题 |
| `project`/`projectName` | 项目 id/名称（旧数据可能为空 → 显示 workspace） |
| `source`/`sourceLabel` | 来源实例 id 与标题 |
| `size`/`hash`/`at` | 文件大小、内容 hash、收集时间 |
| `targetRoot` | 落点目录（workspace 或 station outputDir）；旧行为空 |
| `deliverable` | 文件是否仍可读（targetRoot+name 存在；否则回退 outbox 副本路径） |

过滤：`project`（id）、`source`（实例 id）、`ticket`、`q`（名称/哈希模糊）；排序 `at DESC, id`；分页 `offset/limit`（默认 20，上限 200）。

**详情**（`GET /artifacts/:id`）：
```ts
{
  artifact: ArtifactRow,
  project?: { id, name, key },
  source: { id, label },
  ticket?: { id, title, stage, state, reporter?, mentions? },
  assignment?: { id, state, startedAt?, endedAt?, report?: { state, summary } },
  workerSessionId?: string,           // worker-<ticketId>
  delivery: { path: string, exists: boolean, messageId?: string },
  links: { ticket: string, thread?: string }
}
```
- 反查链：`artifact.ticket` → `ticket.assignments` 最后一个 assignment（或指定 `assignment` 参数）→ `worker-<ticketId>`（`src/executor/dsh.ts` 的命名）。
- `path`：优先 `targetRoot/name`；`targetRoot` 为空（旧数据）时回退 `deliveredTo`（outbox artifacts 目录）或 KV 记录的旧路径；不存在则 `exists:false`。

### 1.2 下载

`GET /artifacts/:id/file`：
- 校验路径：只允许该 artifact 的 `targetRoot/name` 或 `deliveredTo` 内的文件；解析后必须落在允许根内（防 `..` 穿越）；文件不存在 404。
- 响应：`200` + `Content-Type: application/octet-stream` + `Content-Disposition: attachment; filename="<name>"`（文件名安全编码）；`Content-Length`。
- 不缓存为 PDF 等类型；不提供 inline 预览（P6 可加）。

### 1.3 写入补强

- `deliverArtifacts`（`src/app/artifacts.ts`）记录结果回复的消息 id：`engine.reply(...)` 的返回值（Reply.id）写入 artifact value 的 `messageId`（P1a 遗留）。
- 键族收敛：P5 起 artifact 表为唯一索引；`KV.artifacts` 保留写入兼容一个版本（文档注明 P6 删除），读路径统一走表。

### 1.4 测试

- `views.spec`/`http.spec`：列表过滤/分页/q、详情反查链（assignment/session）、旧数据 targetRoot 空回退、下载（200/404/穿越拒绝/Content-Disposition）。
- `artifacts.spec`：messageId 写入；表与 KV 一致性。
- `docs/007` 模块/测试/路由表同步。

## 2. 前端

### 2.1 导航

- `TABS` 增 `artifacts`（标签「产物 / Artifacts」），位于「工作站」之后（与设计 7 页一致：概览/工单源/工作站/产物/…）。
- 路由：`{page:'artifacts'}` 列表；`{page:'artifacts', id}` 详情；列表过滤放 `query`（project/source/q）。

### 2.2 产物列表

- 表格/卡片（沿用现有 `rows` 风格）：名称（可点进详情）、项目、来源、工单、大小、时间、下载按钮。
- 过滤条：项目下拉（workspace 在首）、来源下拉、搜索框（名称/哈希）。
- 空态：无产物时说明「工单报告 ready 后，交付文件会出现在这里」。
- 页头可显示总数与当前筛选。

### 2.3 产物详情

- 元数据：名称、大小、hash、收集时间、落点目录（可复制路径）、交付记录（是否仍可读、结果回复 id）。
- 反查链卡片：**工单**（标题/阶段/汇报人）→ **派工**（id/状态/报告摘要）→ **Worker Session**（`worker-<ticketId>`，按钮打开 Session，复用 `ctx.uiWorkspace.openSession` 与 `navigation.ts` 的就绪校验）。
- 动作：下载、复制路径、打开工单、打开项目。

### 2.4 入口补全

- **工单详情**：新增「产物」块（列表 name/size/hash + 打开产物详情），无产物不显示。
- **项目详情**：产物计数变为链接 → `{page:'artifacts', query:{project}}`；「执行」段工单行显示产物数（可选）。
- **概览**：新增「最近产物」块（最近 5 个，名称/项目/时间 → 详情）。
- **工单源**：源详情可显示该源最近产物（可选，若实现成本低）。

### 2.5 约束

- 客户端零运行时 DSH 导入、CSS 全局 `?raw` + `dt-` 前缀 + 一行一规则、locale 中英同步、无新依赖；下载用 `<a href>` 直连管理路由（同源，无需额外鉴权头；沿用面板的 same-origin 模式——若路由需要 `x-orchestrator-request` 头，则改用 fetch + blob 下载，实现时以现有 http 守卫为准）。
