# 23 设置 Tab 与来源项（Source Types & Accounts）方案

> 需求（2026-11-26）：默认来源只保留「本地文件夹」；GitHub 等改为新增；在「产物」后新增「设置」Tab，先做一个类别「工单源」，其中的来源项包括：本地文件夹、GitHub、Gitee、微信、飞书、钉钉、QQ、Telegram、企业微信应用、邮箱；每个来源项可有多个账号（如 3 个 QQ 机器人）；「工单源 → 添加来源」可选择已有账号或新建，新建同步到来源项；后续按 [dsh-im](https://github.com/xmanrui/dsh-im) 的模式实现各 IM 真实通话。
> 分两步：**P7a 后端基础**（默认来源、来源项目录、账号增删、测试）与 **P7b 面板**（设置 Tab + 工单源设置页 + 添加来源改版）。

---

## 1. 默认来源：只留本地文件夹

现状问题：`SourceRegistry.instancesOf()` 对每个已注册 kind 合成一个默认实例（`registry.ts:137-143`），所以 GitHub 未配置也出现在工单源。

改动：

1. **不再合成默认实例**：`instancesOf(kind)` 在 settings 没有该 kind 的实例时返回 `[]`（仍 claim 声明健康条目，不显示）。保留 `instanceFor()` 的旧数据回退（历史 Trigger/Channel 用 bare kind 仍能解析）。
2. **播种一个本地文件夹实例**：启动时若 settings 里没有任何 `folder` 实例，则创建默认实例：
   - id `folder`（默认实例，id=kind），label「本地文件夹」，enabled=true；
   - config：`inbox = <stateDir>/area/local/inbox`、`outbox = <stateDir>/area/local/outbox`、`operator = 当前系统用户名`、`pollSeconds = 10`；
   - 同时写 Policy 的 `sources.folder`：`allowed=[{id: operator}]`，admission 默认行（仅 listed+direct 通过）；
   - 用 KV 标记 `saa.defaults.seeded`（只播种一次，用户删除后不再复活）。
3. **迁移兼容**：已有 `folder:ops` 等实例的库不动；`github`/`feishu` 无存储实例则不再出现在工单源（catalog 仍可新增）。Setup 继续按可选处理（无 github 配置即不校验）。
4. 目录：`<stateDir>/area/local/inbox|outbox` 与 workspace 分离，避免与工单成果混放；文档写明可改。

验收：新装/当前 profile 刷新后，工单源只剩「本地文件夹」一张卡（若已有 folder:ops 则仍是它）；GitHub 卡消失；catalog 仍能添加 GitHub。

## 2. 来源项目录（10 类）

| kind | 名称 | 状态 | 配置要点（账号级） |
|---|---|---|---|
| `folder` | 本地文件夹 | 已实现 | inbox/outbox/operator/pollSeconds |
| `github` | GitHub | 已实现 | repository/cli/pollSeconds |
| `gitee` | Gitee | 占位（待接入） | token、owner/repo、apiBase |
| `wechat` | 微信 | 占位 | 扫码/机器人凭据（后续） |
| `feishu` | 飞书 | 已实现 | bot cli、chats 等 |
| `dingtalk` | 钉钉 | 占位 | clientId/clientSecret/robotCode |
| `qq` | QQ | 占位 | appId/appSecret |
| `telegram` | Telegram | 占位 | botToken |
| `wecom` | 企业微信应用 | 占位 | corpId/agentId/secret/token/aesKey |
| `email` | 邮箱 | 占位 | imap/smtp/host/user/secret |

- 占位 kind 由新插件 `dsh-superagent-connectors` 注册（`src/sources/connectors.ts`）：只声明 `kind/title/description/schema/fields/health`，无 watch 循环与 channel；实例健康为 `paused`，detail「接入开发中」。
- 每个占位 kind 的 `fields` 提供最小配置表单（必填凭据 + 可选项），schema 用 zod 校验；账号可先创建、保存，不发消息。
- 目录 `skills/dsh-superagent-<kind>/SKILL.md` 预留（后续 IM 实现时补）。
- 添加到 bundle：`tsdown.config.ts` 入口 `connectors`、`package.json` exports、`cordis.patch.yml` insert（enabled），docs 表登记。

## 3. 账号与管理 API

账号 = 一个 Source 实例（现有模型）；一个来源项（kind）可有多个账号。

新增/调整：

- `POST /sources`：已有（kind/key/label/config），默认 enabled=true；占位 kind 允许创建。
- `PATCH /sources/:id`：启停、改 label/config、defaultProjectId（已有）。
- **`DELETE /sources/:id`（新）**：删除账号配置；保护：
  - 若该实例存在未结束工单 → 409 `sourceInUse`；
  - 历史工单保留（视图按 id 回退显示），不级联删除。
- `GET /sources`：保留；新增 `catalog` 已有 `GET source-kinds`，扩展为 10 类（含 `available: boolean` 占位标记）。
- 策略/提示词按实例（0.3.2 已有），新账号默认继承安装默认。

## 4. 面板（P7b）

### 4.1 Tabs

`TABS = ['overview','source','workstations','artifacts','settings']`；齿轮仍指向设置页；设置页类别：

```
设置
├─ 工单源        ← 新
├─ 路由与评估     ← 由 routing 改名/保留
├─ 执行
└─ 部署
```

路由：`{page:'settings', query:{group:'sources'|'routing'|'execution'|'deployment'}}`；旧 group 兼容。

### 4.2 设置 → 工单源

- 左侧：来源项列表（10 类），每项显示图标/名称/账号数/占位标记；右侧：所选类型的说明 + 账号列表。
- 账号行：label、id、状态点（enabled/占位）、配置摘要；操作：编辑（展开配置表单 + 保存条）、启用开关、删除（确认）。
- 「添加账号」：按该类型的 `fields` 渲染表单（默认值来自 schema），提交 `POST /sources`；成功后列表刷新。
- 占位类型：显示「接入开发中」提示，账号可建但工单源不轮询（健康 paused）。
- 提示词/策略：账号行提供「策略提示配置」入口（跳现有 governance 页）。

### 4.3 工单源 → 添加来源（改版）

两步对话框：

1. 选择来源项（10 类，含账号数；占位标记）；
2. 选择账号：已有账号列表（含停用）→ 选中即启用（PATCH enabled=true）并出现卡片；或「新建账号」→ 内联配置表单 → `POST /sources` → 直接启用并出现。
   - 若所选账号已启用，提示「已在工单源」并跳转其详情。
- 保留现有「来源详情/策略提示配置」入口与配置表单。

## 5. 后续 IM 接入路线（参考 dsh-im）

1. **渠道适配器**：每 kind 一个 `SourceKind` 实现（长连接/轮询、消息→Trigger、Channel 发送 @/文件/图片），配置字段对齐 dsh-im（扫码/凭据、多机器人）。
2. **账号即连接**：每账号独立连接状态、工作区、模型/预设；账号下可再分「监听绑定」（群/私聊/仓库），后续把「来源」从账号中拆出（`source.accountId` + listen 配置）。
3. **能力清单**：文本/图片/文件、流式/分段、引用与话题、@ 规则、审批与提问、/命令、主动投递；逐渠道实现并做真实通话测试。
4. **安全**：凭据只存本机凭据存储，状态接口不回传；每渠道权限/白名单。
