# 18 P6a 实施说明：项目会话与项目历史

> 前置：P1–P5 完成，0.2.1 已装（HEAD `43b90fc` 之后，`pnpm check` 绿 · 1269/14）。
> 依据：[10-工作站与产物设计方案.md](10-工作站与产物设计方案.md) §3.2（agent 段）与用户决策「agent = 项目 Session，点击展示该项目工单历史与修改历史」。
> 范围：**项目历史 API + 项目会话（懒创建/打开）+ 工作站 agent 段**。不做 Prompts/Policy 提级（P6b）、实例级健康/具名 Setup（P6c）。

---

## 1. 项目历史（后端）

`GET /projects/:id/history?limit=`：

```ts
{
  project: { id, name, key },
  tickets: [{ id, title, stage, state, ended?{at,outcome}, reporter?, assignments, artifacts, updatedAt }],   // 该站工单，新→旧，默认 50
  artifacts: [{ id, name, ticket, ticketTitle, at, size, hash }],                                               // 该站产物，新→旧
  reports: [{ ticketId, ticketTitle, assignmentId, state, summary, at }],                                      // 最近派工报告
}
```
- 来源：`ticket.projectId`、`artifact.project`、`ticket.assignments[].report`；旧数据（project 空）不计入非 workspace 站。
- 视图放 `src/app/views/projects.ts`（`projectHistory`）；分页只做默认 limit（不新增分页参数，P6b 可按需）。

## 2. 项目会话

- **会话 id**：`project-<projectId>`（确定性，便于幂等打开）。
- **创建/打开（客户端）**：`ctx.sessions.create({ sessionId, cwd: project.scratchDir })`；会话已存在时（创建报 exists/冲突）回退为直接 `openSession(sessionId)`；打开走现有 `navigation.ts` 的 `openKnownSession` 就绪校验与 `ctx.uiWorkspace.openSession`。
- **cwd**：`project.value.scratchDir`（项目副本目录，含 `rules/`）；workspace 项目用 `area/workspace`。
- **seeding**：不自动注入历史消息（避免污染会话）；面板把历史展示在 agent 段，用户可自行引用。若后续需要摘要注入，留 P6c。
- **权限/预算**：会话使用用户默认预设与模型（与手动新建会话一致），不由插件装饰。

## 3. 前端（工作站 agent 段）

- agent 段改为可用：
  - 顶部：「打开项目会话」按钮（首次点击创建后打开；再次直接打开）；说明文案一句话（会话在该项目副本目录中工作，历史见下）。
  - 「工单历史」列表：标题、阶段（本地化）、结束结果、汇报人、派工次数、产物数；点击进工单详情。
  - 「修改历史（产物）」列表：名称、时间、大小、hash、所属工单；点击进产物详情。
  - 「最近报告」列表：工单、assignment、状态、摘要前 2 行、时间。
  - 空态：该项目还没有工单时显示说明。
- 路由不变（`{page:'workstations', id, query.segment:'agent'}`）；移除「P6 提供」禁用占位与对应文案。
