## 1. 关键发现：dsh-im 已具备现成连接层

本机 profile 已安装 `@xmanrui/dsh-im 5.10.0`，它提供：

- **九渠道账号管理**：微信（扫码）、飞书、钉钉、企业微信、企业微信应用、QQ、Telegram、Slack、Discord、WhatsApp；每渠道多机器人，各自连接/工作区/模型/会话独立。
- **出站主动投递 `ctx.dshIm`**：`send(botId, targetId, text, {format})`、`listBots()`、`describeBot(botId)`、`listTargets(botId)`、`createTarget(botId, …)`；HTTP `POST /api/dsh-im/delivery/messages`、Connection RPC `message.send`。九渠道全部支持。
- **入站外部消费 `consumeInbound(botId, {expectedFingerprint, onEvent})` + `replyChecked`**：版本 1 事件含 `channel/botId/fingerprint/eventId/messageId/actor/conversation/mentions/text/reply`；回复按原消息校验（防串会话）；**目前仅飞书/Lark**（opt-in，`consumerMode: 'external-consumer'`；其他渠道保持 dsh-im 自带会话桥）。
- 依赖里已有 `dingtalk-stream`、`@tencent-connect/qqbot-connector`、`@wecom/aibot-node-sdk`、`imapflow` 等成熟 SDK。

**结论：不要重写协议。** 钉钉/QQ/微信的账号、扫码/凭据、长连接、AI Card、文件与图片能力优先复用 dsh-im；缺的是**非飞书渠道的入站消费者接口**。

## 2. 复用方式：移植传输层，不依赖 dsh-im

**用户决定**：把 dsh-im 的实现复用进本项目（MIT，保留署名），**不引入 `@xmanrui/dsh-im` 运行时依赖**，避免本项目被第三方插件绑定；微信先按白名单，群自动回复后续再补。

dsh-im 的渠道层与它的 DSH 会话/命令/审批逻辑强耦合（`bridge`、`controller`、`shared` 共 2.5 万行），整包移植会把无关逻辑带进来。做法是**只移植连接与协议层，重写与工单的对接**：

| 渠道 | 移植来源（upstream 5.10.0） | 保留 | 重写/丢弃 | 依赖 |
|---|---|---|---|---|
| 钉钉 | `src/channels/dingtalk/dingtalk-runtime.mjs`（Stream 连接）、`dingtalk-api.mjs`（发消息/AI Card/文件） | 连接、重连、事件解析、发送 API、错误分类 | bridge/controller 的会话绑定、命令、审批、工作区 | `dingtalk-stream`（公共 SDK） |
| QQ | `src/channels/qq/qq-runtime.mjs`、`qq-controller.mjs` 的连接/发送部分、`markdown-reply`、`qq-mention` | WebSocket 连接、私聊/群 @ 解析、回复与提及 | 会话桥、命令、群历史采集 | `@tencent-connect/qqbot-connector`、`@tencent-connect/qqbot-nodejs` |
| 微信 | `src/channels/weixin/weixin-runtime.mjs`、`weixin-api.mjs`（iLink 客户端与扫码登录） | 扫码登录、长轮询、收发文本（后续文件） | 会话桥、命令、审批 | 无公开 SDK，代码 vendored |

- **合规**：新增 `THIRD_PARTY_NOTICES.md` 条目（MIT、Copyright (c) 2026 xmanrui、upstream 版本与文件映射）；移植文件头注明来源；升级时按 upstream 版本 diff。
- **依赖策略**：钉钉/QQ 使用公共 npm SDK（不是 dsh-im 包）；微信 iLink 无公开 SDK，直接移植并保留 MIT 声明。
- **凭据**：存我们自己的 settings（secret 掩码、不回传客户端）；微信扫码 token 存 `<stateDir>/` 下 `0600` 文件；日志不出现 token。
- **不移植**：`shared/` 的会话桥、workspace、审批、deferred delivery、artifact delivery 等；这些由我们现有 Ticket/Outbox 机制承担。

## 3. 内部 IM 适配器接口（统一）

每个渠道实现一个适配器，`SourceKind` 的 watch 循环为每个实例创建/销毁它：

```ts
interface ImAdapter {
  connect(config: unknown, handlers: {
    onMessage(event: ImEvent): Promise<void>   // 入站消息（已去重前）
    onStatus(state: 'starting'|'ready'|'paused'|'error', detail: string): void
  }, signal: AbortSignal): Promise<void>
  send(route: ImRoute, text: string, opts?: { format?: 'plain'|'markdown' }): Promise<'sent'|'gone'>
  close(): Promise<void>
}
```

- **账号**：一个实例 = 一个机器人凭据（钉钉 clientId/secret、QQ appId/secret、微信扫码 token）；支持同渠道多实例。
- **入站**：`onMessage` → 白名单/会话类型/@ 过滤 → 去重（`eventId`/`messageId` 存 KV 7 天）→ Trigger（`source=<kind>:<instance>`，`thread=<kind>:<instance>:<conversationId>[:<threadId>]`，`meta` 带回复路由）。
- **授权**：仅白名单人类可发起；机器人/自己消息不授权；微信默认仅私聊白名单，群回复后续再开。
- **出站**：`send(route, text)`，route 为入站事件携带的不可伪造路由；失败按现有 Outbox 重试；`reply-result-unknown` 不盲目重发。
- **健康**：每实例一条；连接断开/重连/凭据失效分别上报 detail；3 次连续失败进 error。
- **降级**：未配置凭据 → paused；SDK 缺失/依赖未安装 → error 并提示；不影响其他来源。

## 4. 远程文件夹（SSH/SFTP）——本轮实现

新增 kind `remote`（远程文件夹），与本地文件夹同构的投件/回执模型，传输走 SFTP。

**配置**：`host`、`port`(22)、`username`、`identityFile`（私钥路径）、`knownHosts`（known_hosts 文件路径）、`hostKeySha256`（可选指纹钉死）、`inbox`、`outbox`（远端绝对路径）、`pollSeconds`(30)、`maxFileBytes`(1 MiB)、`operator`。

**安全要求（硬性）**：

1. **只用密钥认证**：`BatchMode=yes`、`IdentitiesOnly=yes`、不存密码、不读 ssh-agent（显式 `-i`）。
2. **主机密钥强校验**：`StrictHostKeyChecking=yes` + `UserKnownHostsFile=<配置>`；缺失/不匹配即报错暂停，**绝不** `accept-new`；可选 `hostKeySha256` 再做一次指纹比对。
3. **不执行 shell**：只用 `sftp -b -` 批处理（`ls/get/put/rename`），路径限定 `[A-Za-z0-9._/-]+`，拒绝 `..`、换行、引号、通配符；inbox/outbox 必须是绝对路径。
4. **限额**：单文件 ≤ `maxFileBytes`，每轮最多 20 个文件；超时（连接 15s、单命令 30s）；失败按现有连续失败阈值进 health。
5. **最小权限**：远端建议专用只读写目录、专用 key（`command=` 限制可选）；文档给出 sshd 最小配置示例。
6. **本地临时文件**：写入 `<stateDir>/area/remote.tmp/<instance>/`，处理后删除；不落长期副本。
7. **幂等**：处理后 `rename` 到 `inbox/.done/`；回复文件写 `outbox/<messageId>.md`，重试用同名覆盖。

**流程**：`ls inbox` → 跳过 `.done`/隐藏/超限 → `get` 到临时目录 → 解析为 Trigger（`source=remote:<instance>`，`thread=remote:<instance>:<file>`，汇报人=operator）→ 工单完成 → 回执 `put` 到 outbox → 源文件 `rename` 入 `.done`。
