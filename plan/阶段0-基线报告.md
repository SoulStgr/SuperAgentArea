> 目标：确认原型在本机 Windows + DSH `0.2.2-rc.5` 环境下 `pnpm check`（typecheck + test + build）全绿，并记录与上游 POSIX 假设的差异。

## 3. 初始失败与分类（40 项 / 9 文件 → 0）

初次 `pnpm test`：**1157 passed / 40 failed / 17 unhandled errors**。全部为 Windows 移植性问题，**未发现 DSH 0.2.2-rc.5 的 API 漂移**（按锁文件的 0.2.1-alpha.2 编译与行为均通过）。

| 类别 | 涉及 | 处理 |
|---|---|---|
| 真实跨平台测试缺陷 | `docs.spec`（`lastIndexOf('/')` 取文件名、表格路径未归一、CRLF 行尾）、`prompts.spec`（临时目录跨盘 `relative()`）、`environment.spec`（`--show-origin` 引号、PATH 分隔符）、`runtime.spec`（git config 转义、PATH 分隔符）、`commands.spec`（MSYS sh 以 exit code 2304 报告 SIGKILL） | **按跨平台语义修复**，不跳过 |
| POSIX 工具依赖（可由环境满足） | `commands.spec` 的 `env`/`sh`/`sleep`/`echo`、`environment.spec` 的 `sh -c` | `vitest.setup.ts` 在 win32 上把 Git `usr/bin` 前插 PATH，测试真实执行 |
| Node 无法直接执行 shebang 脚本 | `deployment.spec`（3）、`environment.spec`（3）、`sources.spec` Feishu consumer（7） | `it.skipIf(win32)` / `describe.skipIf(win32)`，注释说明原因；对应产品缺口见 §5 |
| POSIX 权限位 | `store.spec`（目录 0700 / 文件 0600） | `it.skipIf(win32)`：Windows 用 ACL，chmod 尽力而为 |
| POSIX-only 服务脚本 | `service-script.spec`（fcntl/tmux/sleep，13 项 + 未处理错误） | `vitest.config.ts` 在 win32 上排除该 spec |

## 4. 测试环境适配（已提交）

- `vitest.setup.ts`（新增）：win32 上从 PATH 中的 `Git\cmd` 推导 `Git\usr\bin` 并前插，使 POSIX 工具型测试真实运行。
- `vitest.config.ts`：`setupFiles` 注册上述文件；win32 上 `exclude` 增加 `tests/service-script.spec.ts`。
- 14 个跳过项：`environment` 3、`deployment` 3、`sources`(Feishu consumer) 7、`store` 1。

## 5. 产品侧 Windows 缺口（阶段 1 E2E / 阶段 4 处理）

| # | 缺口 | 影响 | 计划 |
|---|---|---|---|
| 1 | **worker shim 是 `#!/bin/sh` 脚本**（`src/infra/environment.ts`），Windows CreateProcess 不能执行无扩展名脚本 | worker 的 `gh`/`lark-cli`/被禁命令 shim 在 Windows 上不可用；git 自身能跑 shebang（askpass 测试通过），Node spawn 不能 | 阶段 1 E2E 前补 `.cmd`/`.ps1` shim 或等价机制 |
| 2 | 服务脚本仅 POSIX（Python `fcntl`/`tmux`） | 无头 Linux 部署工具；桌面版在进程内运行，不受影响 | 桌面场景不阻塞；如需 Windows 服务化再评估 |
| 3 | POSIX 权限位在 Windows 无效 | 状态目录/数据库保护依赖 ACL | 阶段 4 安全加固纳入 |
| 4 | 快照文件为 CRLF | 打包文件读取已 `\r\n`→`\n`（`skill-files.ts`）；文档解析已兼容 | 新增文件一律 LF |
