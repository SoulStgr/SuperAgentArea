## 0. 一句话

P1 把三个"一等对象"落库：**Project（工作站/项目组）**、**SourceInstance（多实例来源）**、**Artifact（产物索引）**；工单补 `projectId/sourceId/reporter/mentions`；目录从"每工单一个 work 目录"改为 **`<stateDir>/area/` 下的 workspace + 工作站成果目录 + `<station>.work/` 副本目录**；未归属项目走 **Eval 拒绝（`needsProject`）+ 回答重评**。

## 1. 地址模型（新增需求：指定文件夹 / 仓库 / 个人临时工作夹）

用户要求：**发起人或工作者可以指定具体文件夹或仓库作为工作站；个人单次使用时可直接指定工作文件夹**。因此 Project 的地址是多元的：

| 形态 | `location` | 成果目录（outputDir） | 副本目录（scratchDir） | 适用 |
|---|---|---|---|---|
| **托管**（默认） | `{type:'managed'}` | `<stateDir>/area/<key>/` | `<stateDir>/area/<key>.work/` | 新建工作站，不指定地址 |
| **指定文件夹** | `{type:'folder', path:'D:\\work\\aps'}` | 用户指定目录（直接落根，见 §9-1） | 默认 `<stateDir>/area/<key>.work/`（见 §9-2） | 已有工作文件夹的个人/团队 |
| **指定本地仓库** | `{type:'repo', path:'D:\\git\\aps'}` | 仓库内 `artifacts/`（或约定目录） | `<stateDir>/area/<key>.work/`（worktree 父目录） | 代码类工作站 |
| **指定远程仓库** | `{type:'repo', url:'git@github.com:org/aps.git', branch:'main'}` | 同本地仓库 | 同上（clone 到 `<key>.work/repo`） | 共享仓库 |
| **个人临时（adhoc）** | `{type:'folder', path:'D:\\临时\\整理'}` + `kind:'adhoc'` | 指定文件夹 | `<stateDir>/area/workspace/.work/<ticketId>/` | 单次任务，不建长期工作站 |

补充规则：

- `workspace` 是内置的 `kind:'workspace'` 项目，`location` 为 `{type:'managed'}` 但成果根固定为 `<stateDir>/area/workspace/`，承接无项目/临时工单。
- `key` 由名称归一化生成（`aps-填报`），冲突时加 `-2` 等后缀；`aliases[]` 收来源侧的项目名。
- **谁能指定外部路径**（安全，已决：**agent 建议 + 人确认**）：编排模型可以在未命中时提出**地址提案**（`needsProject` 决定的 `proposal` 字段），但只有**人**确认后才创建 Project 并开工——面板确认，或来源会话里被允许的人明确回复确认。模型不得绕过确认直接建站。地址校验：绝对路径、存在或可创建、可写、非系统保留目录；记录提案人与确认人（审计）。
- **仓库站的并发**：每工单一个 git worktree（`<key>.work/worktrees/<ticketId>`）+ 分支 `saa/<ticketId>`（见 §9-3）；完成后由人或规则合并。

## 2. 实体与 DDL（schema 12）

### 2.1 新表

```sql
CREATE TABLE IF NOT EXISTS project (
  id         TEXT PRIMARY KEY,          -- 'prj_' + key 的稳定 id
  key        TEXT NOT NULL UNIQUE,      -- slug：aps-填报
  value      TEXT NOT NULL,             -- JSON：见 §2.2
  status     TEXT NOT NULL,             -- 'active' | 'archived'
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS project_status ON project(status, updated_at);

CREATE TABLE IF NOT EXISTS artifact (
  id       TEXT PRIMARY KEY,            -- sha1(ticketId + ':' + name) 前 16 位
  ticket   TEXT NOT NULL,
  project  TEXT,                        -- NULL = 无项目（旧数据）
  source   TEXT NOT NULL,               -- 来源实例 id
  name     TEXT NOT NULL,               -- 相对路径（正斜杠）
  value    TEXT NOT NULL,               -- JSON：hash,size,at,targetRoot,deliveredTo,messageId
  at       TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS artifact_ticket    ON artifact(ticket);
CREATE INDEX IF NOT EXISTS artifact_project_at ON artifact(project, at);
CREATE INDEX IF NOT EXISTS artifact_source_at  ON artifact(source, at);
CREATE INDEX IF NOT EXISTS artifact_at         ON artifact(at);
```

### 2.2 `project.value` JSON

```ts
interface ProjectValue {
  name: string
  kind: 'workspace' | 'station' | 'adhoc'
  location:
    | { type: 'managed' }
    | { type: 'folder'; path: string }
    | { type: 'repo'; path?: string; url?: string; branch?: string }
  outputDir: string      // 成果目录（绝对路径，创建时解析并落库）
  scratchDir: string     // 副本目录（绝对路径）
  rulesDir: string       // 固定规则目录（默认 <scratchDir>/rules）
  sourceIds: string[]    // 关联的来源实例
  aliases: string[]
  specifiedBy?: { source: string; id: string; name?: string }  // 谁指定了外部地址
  archivedAt?: string
  retentionUntil?: string  // adhoc 的保留期
}
```

### 2.3 既有表变更（JSON 内字段，无需 ALTER）

| 表 | 字段 | 说明 |
|---|---|---|
| `ticket` | `projectId: string` | 建单时写入；旧数据回填 `workspace` |
| | `sourceId: string` | 来源实例 id（旧数据 = 触发 kind） |
| | `reporter: PersonRef` | 汇报人，默认触发人 |
| | `mentions: PersonRef[]` | 被 @ 的人 |
| | `workspace`（目录） | 沿用 `execution.directory`，值改为 area 布局 |
| `decision` | `reason.code = 'needsProject'` | 未归属项目；`reason.values = { candidates[], proposal? }`——`proposal` 是 agent 的地址提案（`{name, location, proposedAt}`），需人确认；提问文本由系统生成 |
| `disposition` | 不变 | 触发处置 |

### 2.4 设置结构（多实例来源 + 默认归属）

```ts
settings.sources = {
  [instanceId: string]: { enabled: boolean; config: Record<string, unknown>; defaultProjectId?: string }
}
// instanceId 形如 'folder:ops'、'github:zhangsan/aps'；旧数据 sources[kind] → 实例 id = kind
settings.policy.sources = { [instanceId: string]: SourcePolicyPart }  // 与来源实例同键
```

## 3. 查询与索引

| 查询 | 来源 | 索引 |
|---|---|---|
| 工单源卡：该源待处理工单数、24h 统计 | `ticket` 按 `source`（JSON 字段）→ 需要反范化列或内存过滤 | 建议给 ticket 加**生成列** `source_id`/`project_id` + 索引（SQLite generated column），避免全表 JSON 扫描 |
| 工作站卡：工单数/产物数/最近活动 | `ticket` 按 project、`artifact` 按 project | 同上 + `artifact_project_at` |
| 产物列表/详情/反查 | `artifact` 全表/按 ticket/project/source | 上述索引 |
| 项目历史 | `ticket` + `artifact` + `decision` 按 project/thread | 组合索引 |
| 未归属问题 | `decision` where `reason.code='needsProject'` 且未回答 | 需要 `decision` 增生成列 `code` 或小而快的全表（量小） |

> 现有 `trigger_thread` 已有 `at` 索引；ticket 表目前仅 `id` 主键，P1 必须补 `source_id/project_id` 生成列与索引，否则工单源/工作站页会全表扫。

## 4. 目录模型与工单执行

```
<stateDir>/area/
├── workspace/                      # kind=workspace 的成果根（也是无项目工单执行根）
│   └── .work/<ticketId>/           # 临时工单副本/脚本/日志
├── <station>/                      # 托管/指定文件夹站的成果目录（指定文件夹时 outputDir 指向外部路径）
└── <station>.work/                 # 副本目录
    ├── rules/                      # 固定规则（AGENTS.md / 验收口径）
    ├── <ticketId>/                 # 工单工作区（manifest 的 deliver/ 在这里）
    └── worktrees/<ticketId>/       # 仓库站的 git worktree
```

- 工单执行目录：`station ? <scratchDir>/<ticketId> : <stateDir>/area/workspace/.work/<ticketId>`。
- `deliver/` 仍是 worker 唯一交付约定；`ready` 时按归属提升：`targetRoot = station ? outputDir : <area>/workspace/`。
- 提升规则：同名冲突时 `<name>.<ticketShortId>.<ext>`（§9-1）；`artifact.targetRoot` 记录实际落点，副本目录不索引。
- 旧工单：`execution.directory` 原样保留（只读兼容），不迁移文件。

## 5. 项目归属链路（P1 数据 + P2 行为）

1. **来源实例默认归属**：`settings.sources[id].defaultProjectId`。
2. **事件提示**：`Trigger.meta.projectHint`（folder：`PROJECT.md` 或任务夹名；GitHub：仓库映射/标签；IM：会话或项目名）。
3. **解析**：`ProjectRegistry.resolve(hints) → projectId | candidates`（名称/别名/地址归一化匹配）。
4. **未命中**：Decision `stop` + `needsProject`，生成**确定性提问**（候选列表来自 registry，不由模型编造）；`POST /triggers/:id/answer-project` 或来源回答 → 新 Trigger → 重评 → 建单。
5. **指定地址**：两条路径——①人直接给 `new: { name, location }`；②agent 提案（`proposal`），人确认后按其建站。校验通过才建 Project（托管/文件夹/仓库/adhoc），并记录提案人与确认人。

## 6. API 契约（新增/变更）

```ts
// 项目
GET    /projects?status=active|archived
GET    /projects/:id                    // { project, sources, tickets(摘要), artifacts(摘要), stats }
GET    /projects/:id/history            // 工单历史 + 修改历史（artifacts 版本 + 报告 + 结束）
POST   /projects                        // { name, location?, kind? } → project；location 缺省 = managed
PATCH  /projects/:id                    // 改名/别名/归档/关联来源
POST   /triggers/:id/answer-project     // { projectId } | { new: { name, location } } | { confirmProposal: true }
// 来源实例
GET    /sources                         // 多实例 + stats + 工单分桶
POST   /sources                         // { kind, label, config } → instance
PATCH  /sources/:id                     // 启用/配置/默认项目
// 产物
GET    /artifacts?q=&project=&source=&ticket=&offset=&limit=
GET    /artifacts/:id                   // 反查链
GET    /artifacts/:id/file              // 下载（校验归属与可读）
// 工单
GET    /tickets?source=&project=&state=
GET    /tickets/:id                     // 增加 reporter/mentions/project/artifacts 摘要
```

错误码沿用 `USER_ERRORS`；新增：`projectUnknown`、`projectLocationInvalid`（路径/仓库校验）、`projectSpecifiedByModel`（模型不得指定外部地址）。

## 7. 迁移（v11 → v12）

单事务，失败回滚并保持旧版本（沿用 `migrateTo11` 的范式）：

1. 建 `project`/`artifact` 表与索引；ticket 生成列。
2. 插入内置 `workspace` 项目（`key='workspace'`, `kind='workspace'`）。
3. 旧 ticket：`projectId='prj_workspace'`（内置项目 **id 是 `prj_workspace`、key 是 `workspace`**，引用一律用 id）、`sourceId=origin 触发的 source`、`reporter=触发 actor`、`mentions=[]`（actor 名称可从 store 的 actor 解析，取不到就只留 id）。
4. 旧 `KV.artifacts(ticket)` → `artifact` 行（`project='prj_workspace'`，`source` 取自 ticket 的 origin 触发，`targetRoot=''`、`deliveredTo` 记旧 outbox 路径）。
5. 设置：`sources[kind]` → `sources[instanceId=kind]`；`policy.sources` 同键迁移；`defaultProjectId` 置空。
6. 写 `KV.store.schema = 12`。

回滚策略：迁移在事务内完成；失败时数据库保持 v11，启动报错并保留原库（现有 Store 行为）。

## 8. 并发、安全与审计

| 主题 | 设计 |
|---|---|
| 同一工作站多工单 | 工作区按 ticket 隔离（`<scratch>/<ticketId>`）；成果提升冲突加短 id；仓库站用 worktree+分支 |
| 外部路径授权 | 仅“人”可指定（面板/来源里的人明确给出）；模型只做匹配；路径校验 + 记录 `specifiedBy` |
| 仓库凭据 | 复用现有 git/gh 隔离环境（`src/infra/environment.ts`）；remote clone 在 `<scratch>/repo` |
| 审计 | `specifiedBy`、`project.archivedBy`、artifact 的 `deliveredTo` 落 JSON；后续阶段 4 并入 append-only 审计表 |
| 数据保留 | adhoc 项目完成后自动归档，行保留（§9-4 定保留期）；副本目录可清理，成果目录不动 |

## 9. 决策记录（2026-11-25，全部关闭）

1. **外部地址的指定权**：**agent 建议 + 人确认**（`proposal` 存于 `needsProject` 决定；确认后才建站/开工；记录提案人与确认人）。
2. **指定文件夹站的落点**：成果**直接落用户指定的工作站目录根**（成功即落在用户工作站里）；副本 `.work/` 放插件根目录下 `<stateDir>/area/<key>.work/`。
3. **指定文件夹站的副本目录**：`<stateDir>/area/<key>.work/`（已并入第 2 条）。
4. **仓库站的执行方式**：每工单 **git worktree + 分支 `saa/<ticketId>`**。
5. **adhoc 项目保留**：完成后**自动归档、保留历史行**；成果文件留在指定文件夹。
6. 外部路径校验：绝对路径、存在/可创建、可写、非系统保留目录（个人使用友好，不强制白名单）。
