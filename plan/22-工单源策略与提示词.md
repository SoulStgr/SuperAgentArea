# 22 工单源策略与提示词（方案与实施）

> 目标：把「提示词」与「策略」从安装级一级页下沉到**每个工单源实例**。每个工单源拥有自己的策略与提示词，入口在工单源的操作项「策略提示配置」。
> 状态：已完成（待提交）。实施完成记录见 §8。

## 1. 现状与问题

- **提示词**：安装级单份 `PromptConfig`（`KV.prompts.revision` / `prompt-version:<n>`），主 Session 与所有 worker 共用；内置段落里带 `skill/feishu`、`skill/github` 两段；`Prompts.skills()` 不分来源，把所有 Session 都注册成「飞书技能 + GitHub 技能」。
- **策略**：`policy` 块 = 全局 `rules` + `policy.sources[<实例 id>]`（allowed / bots / syncChat / admission）。面板策略页把全局规则与各来源部分混在同一页。
- **问题**：来源无法拥有自己的提示词；技能与来源没有绑定（folder 来源的 worker 也会装 GitHub/飞书技能）；策略页仍是「全局规则 + 多来源」的混合页，与「每个来源一份配置」的产品直觉不符。

## 2. 目标形态

1. 每个来源实例（`<kind>` 或 `<kind>:<key>`）有独立的**策略**与**提示词**；工单源卡片/详情页的操作项新增「策略提示配置」。
2. 一级 Tab 收敛为 **概览 / 工单源 / 工作站 / 产物**；提示词、策略不再是一级页。
3. 提示词：
   - 按来源版本化保存（团队三段、内置段落覆盖、技能）。
   - 内置段落中**去掉** `skill/feishu`、`skill/github`（不再作为可覆盖的内置段落）。
   - 技能区展示并自动挂载**该来源 kind 的默认技能**（`github` 源 → GitHub 技能；`feishu` 源 → 飞书技能；`folder` 源 → 文件夹技能；以后 `dingtalk` / `qq` / `wechat` / `remote` 等按同名 `skills/dsh-superagent-<kind>/SKILL.md` 自动出现）。
4. 策略：
   - 准入名单（allowed）、机器人（bots）、同步聊天（syncChat）、准入矩阵（admission）继续按来源保存，编辑入口移到来源。
   - `rules` 支持按来源覆盖（缺省继承安装默认 rules），因此每来源的「准入规则」也可独立调整。
   - 评估设置（`eval`：mode / timeoutSeconds / model）仍是安装级，移到设置齿轮的「路由与评估」组；主 Session 的提示词默认配置也放在该组（兼容旧数据，只读展示可选）。
5. 生效规则：
   - 某工单的 **worker Session**：提示词与技能 = 该工单**来源实例**的配置；`mandate` 里用到的规则 = 该来源的策略规则。
   - **主 Session**：提示词 = 安装级默认配置；技能 = 已配置来源 kind 的默认技能并集 + 安装级团队技能；Policy 段按来源列出各来源启用的规则。
   - 保存后按现有 revision 机制在「下一次模型请求」生效，不重启、不取消、不唤醒 Session。

## 3. 数据模型

| 数据 | 存储 | 说明 |
| --- | --- | --- |
| 每源提示词 | `KV.prompts.revision`（安装级默认，沿用旧键） + `prompt-revision:<instanceId>`；版本 `prompt-version:<n>`（旧） / `prompt-version:<instanceId>:<n>`（新） | 未保存过的来源**继承安装级默认配置**；首次保存写入该来源自己的版本链 |
| 每源策略 | `settings.policy.sources[<instanceId>]`，新增可选 `rules: Rule[]` | 没有 `rules` 时使用安装默认 `policy.rules`（向后兼容，不迁移数据） |
| 策略保存通道 | `SettingsBlock` 新增 `policy:<instanceId>`，独立 block revision | `PUT settings/policy:<id>`，乐观并发 |
| 内置技能 | 扫描 `skills/dsh-superagent-*/SKILL.md` 得到 `bundledSkills: Record<kind, Skill>` | 删除硬编码 feishu/github 两段 |
| 会话 revision 绑定 | `KV.sessions.prompts(sessionId)` 由 `number[]` 改为 `string[]`（`<scope>#<revision>`，主 Session 的 scope 为空串） | 资源/工具读取该 Session 实际用过的版本 |

无 SQLite schema 迁移：旧数据继续可用；旧配置里的 `skill/feishu`、`skill/github` 覆盖在下次保存时按现有「部件已移除即丢弃」规则清理。

## 4. 接口

| 请求 | 说明 |
| --- | --- |
| `GET sources/:id/prompts?revision&offset` | 该来源的提示词视图（结构同现有 PromptsView）：current/defaults/sections/parts/defaultChanged/history/defaultSkills |
| `PUT sources/:id/prompts {config, baseRevision}` | 保存该来源提示词，返回 revision 与 context_delivery |
| `POST sources/:id/prompts/preview` | 预览该来源提示词 |
| `PUT settings/policy:<id> {value, revision}` | 保存该来源策略（rules + allowed + kind 字段 + admission） |
| `GET settings` | `sources[].policy` 增加 `rules`（生效值）与 `inherited`（是否继承安装默认） |
| 现有 `GET/PUT prompts` | 保留为安装级默认（主 Session 工具与兼容用），面板不再使用 |

## 5. 面板

- **工单源页**：来源卡片操作项 `打开来源` + **`策略提示配置`**；来源详情页头同样入口。
- **来源页分段**：`概览`（现有：配置/统计/工单/事件）与 `策略与提示词`（内部分「策略」「提示词」两个子区）。
  - 策略子区：规则列表（每源，缺省显示继承的安装默认并提示可覆盖）、允许名单、机器人、同步聊天、准入矩阵、策略同步。
  - 提示词子区：团队三段、内置段落（不含来源技能）、技能（默认技能只读 + 团队技能）、版本历史、预览、保存条。
- **设置齿轮**：`路由与评估`（eval 设置 + 主 Session 提示词）、`执行`、`部署`。
- 文案 zh/en 同步；深链不做（与既有约束一致）。

## 8. 实施完成记录

> 状态：**已完成（待提交）**。单次提交，提交名 `shsren-saa`。

### 8.1 完成内容

- **每源策略与提示词。** 每个来源实例（`<kind>`、`<kind>:<key>`）拥有自己的策略与提示词；入口为工单源卡片与详情页的「策略提示配置」，来源页分段为 `概览 / 配置 / 策略与提示词`（后者内部再分 `策略 / 提示词`）。
- **面板信息架构。** 一级 Tab 收敛为 `概览 / 工单源 / 工作站 / 产物`；策略、提示词不再是一级页；「最近决定」是非一级内部页（概览可进）；设置齿轮三组 `路由与评估 / 执行器与执行环境 / 部署`；旧 Prompts / Policy / Eval / Settings 路由按新位置重定向（提示词与策略开来源页，Eval 段开 Routing and Eval，决定列表保留自己的页）。
- **提示词。** `PromptConfig` 按来源实例版本化（`prompt-revision:<scope>` / `prompt-version:<scope>:<n>`）：未保存的来源继承安装级默认且面板标注 inherited；主 Session 用安装级默认；worker 按 `ticket.sourceId` 读取其来源配置。内置段落移除 `skill/feishu`、`skill/github`（旧覆盖在下次保存时按「部件已移除即丢弃」清理）。默认技能按来源 kind 从 `skills/dsh-superagent-<kind>/SKILL.md` 自动扫描挂载，现为 `github` / `feishu` / `folder`，未来 `dingtalk` / `qq` / `wechat` / `remote-host` 同理；主 Session 的技能并集 = 已配置来源 kind 的默认技能 + 团队技能，团队技能仍可加。会话 revision 绑定由 `number[]` 改为 `<scope>#<revision>`。
- **策略。** `policy.sources[<id>].rules` 变为可选（缺省继承安装默认 rules），`rulesFor(settings, source)` 统一取用；`allowed` / `bots` / `syncChat` / `admission` 继续按来源。保存通道新增独立 block `policy:<id>`（独立 block revision，乐观并发）；策略版本、`policyEffects`、Mandate 重校验、`admitsInferred`、评估判定与主 Session 的 Policy 段均按来源规则。主 Session Policy 段在存在来源自有规则时按来源列出规则（继承中的来源标注 installation default rules），否则沿用安装默认规则列表。
- **设置与历史。** `GET settings` 的 `sources[].policy` 增加 `rules`（生效值）、`inherited`、`revision`、`value`；设置历史按来源展示规则改动（新增/改名/改指令/启停/删除）。执行器的 `mandateInstructions` 用该工单来源的规则文本。
- **新增文件。** `skills/dsh-superagent-folder/SKILL.md`、`src/client/policy.tsx`。
