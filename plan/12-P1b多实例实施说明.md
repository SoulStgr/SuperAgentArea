# 12 P1b 多实例来源：实施说明（P1a 完成后执行）

> 输入：`plan/10-工作站与产物设计方案.md` v1.0、`plan/11-P1数据模型与接口设计.md`。
> 范围：**只做来源多实例的后端模型与迁移**（settings/policy/registry/三个 kind 的配置与循环）；不改 UI（工单源页面在 P3）、不做项目归属（P2）。

---

## 1. 实例身份

- `instanceId = <kind>:<key>`，例如 `folder:ops`、`github:zhangsan-aps`；key 由用户命名/来源标识归一化（小写、非字母数字转 `-`）。
- 旧数据：`settings.sources[kind]` 只有一个实例 → 迁移为 `instanceId = kind`（无冒号，保持旧 id，避免历史 Trigger/Thread/Policy 断链）。
- `Trigger.source` / `ThreadRef.source` / `ChannelRef.source` **新数据写实例 id**；旧数据保留 kind。解析统一走 `SourceRegistry.kindOf(source)`：
  - 若 `settings.sources[source]` 存在 → 取其 `kind`；
  - 否则若 `kind === source` 且已注册 → 视为旧实例；
  - 否则视为未知来源（现有行为：不监听/无上下文）。

## 2. 设置结构

```ts
settings.sources = {
  [instanceId]: {
    kind: 'folder' | 'github' | 'feishu',   // 新增：实例属于哪个 kind
    enabled: boolean,
    config: Record<string, unknown>,         // 该 kind 的「单实例」配置
    label?: string,                          // 面板可读名（可选，默认 kind 标题 + key）
    defaultProjectId?: string                // P2 用，P1b 先透传/留空
  }
}
settings.policy.sources = { [instanceId]: SourcePolicyPart }   // 与实例同键
```

**迁移**：旧 `sources[kind] = {enabled, config}` → `sources[kind] = {kind, enabled, config}`；旧 `policy.sources[kind]` 键不变（instanceId=kind）。

## 3. 各 kind 的配置形态（从「单实例里的多行」改为「一实例一配置」）

| kind | 旧 config | 新 config（单实例） |
|---|---|---|
| folder | `{folders:[{id,inbox,outbox}], operator, pollSeconds}` | `{inbox, outbox, operator?, pollSeconds}`；旧 `folders[]` 每行生成一个实例 `folder:<id>` |
| github | `{repository, cli, pollSeconds, failuresBeforeError, observe*}` | 不变（本就是单仓库一配置）；实例 id `github:<repository 归一化>` |
| feishu | `{chats:[…], directMessages, …}` | 不变（一实例=一个 bot）；实例 id `feishu`（后续多 bot 再拆） |

- `SourceKind.schema` 的含义从「kind 级配置」变为「实例级配置」；`fields` 不变（去掉了 folder 的 `folders` 行编辑器，改由「添加来源」创建实例）。
- folder 的 `operator` 保留在实例配置里；`policy.rows` 对 folder 返回**单行**（row id = instanceId，不再是 folder row id）。
- **Thread 键**：新数据 `ThreadRef = { source: instanceId, id: rel }` → `threadKey = '<instanceId>:<rel>'`（如 `folder:ops:demo-1.md`）；旧数据 `{source:'folder', id:'ops:demo-1.md'}` 得到**同一字符串**（迁移里 folder 实例 id 取旧 row id，恰好无缝）；`kindOf` 按 `source` 解析实例/kind。
- `SourceKind.policy.rows(config)` 收到的已是单实例 config；github 仍是 issues/pulls/comments/ci 四行。
- `SourceKind.find` / `threadContext` / `environment.values` 的 `config` 参数含义同上（单实例配置）。

## 4. Registry 改动

- `SourceRegistry.instances()`：返回 `settings.sources` 中的全部实例（按 kind 注册顺序 + instanceId 排序）；对已注册但**无 settings 条目**的 kind，仍合成一个默认实例（id=kind，config=schema 默认，enabled=true）——保持「装上即可用」的行为。
- `resolve(instance)`：用 `settings.sources[instanceId].config` 校验；失败 → disabled + schema 默认值（沿用现有 resolve 逻辑）。
- `scope(trigger)`：按 `kindOf(trigger.source)` 找 kind，按 `instanceId` 找实例配置。
- `threadContext` / `send` / `link` / `find` / `repliesTo` 全部按 `kindOf(source)` 路由。
- `SourceHost.context(kind)` 目前按 kind 取健康条目与配置；新增 `context(instance)`（P1b 内部用），`config<C>(instanceId)` 返回该实例配置。
- 健康条目：**P1b 保持 kind 级**（`folder`/`github`/`feishu` 一个条目，多实例共享）；实例级健康（`folder:ops` 等）留到 P3 面板需要时再加（届时 `kind.health` 生成规则改为按实例）。

## 5. 插件循环改动

| 插件 | 改动 |
|---|---|
| folder-watch | `watchFolder` 遍历 `ctx.instances('folder')`，每个实例一个轮询轮次（各自的 inbox/outbox/operator/pollSeconds）；`KV.folder.*` 键族按 instanceId 分片（现状按 row id，改成 instanceId 即可）；健康仍报 `folder`，detail 汇总各实例条目数/失败 |
| github-watch | 遍历 `ctx.instances('github')`，每个实例独立轮询（repository/cli/cursor）；`KV.github.*` 按 instanceId 分片（旧数据回退到 kind 键）；健康报 `github` 汇总 |
| feishu-watch | 单实例不变；`ctx.config('feishu')` 改为按实例解析（id='feishu'） |

## 6. 迁移（并入 schema 12 迁移或独立执行）

在 P1a 的 `migrateTo12` 内追加（或新增 `migrateSettingsToInstances`，由 Runtime 启动时调用一次并写版本标记）：

1. 读 settings 快照；`sources[kind]` → `{kind, enabled, config}`；folder 的 `folders[]` 拆成多个实例，**每行一个**：`folder:<row.id>`，config 取 `{inbox: row.inbox, outbox: row.outbox, operator, pollSeconds}`；旧 `row.id` 原样作为 key（若冲突加后缀）。
2. `policy.sources[kind]` → 键不变；folder 的 admission `rows` 按实例返回（row id = instanceId）。**Thread 键兼容**：旧 folder 键为 `folder:<rowId>:<rel>`（`src/sources/folder.ts` 的 `thread = row.id + ':' + rel`）；新键为 `<instanceId>:<rel>`，迁移后 folder 实例 id 取旧 rowId，故字符串相同，历史 Thread/Trigger/Decision 仍可解析。github/feishu 的旧 thread 键（`github:<number>`、`feishu:<chat>:<topic>`）在「实例 id = 旧 kind」下不变。
3. 写 `settings.sources` 新结构并保存（走 Store.saveSettings 或直接写 kv 快照，保持 revision 语义：**迁移写入记为新 revision，origin='migration'**）。

> 实现时先读 `src/policy.ts` 的 SettingsSchema 与 `src/app/store.ts` 的 saveSettings 语义，按现有 revision/快照机制实现；不要在迁移里绕过版本校验。

## 7. 测试清单

## 8. 验收

`pnpm check` exit 0；旧库（v11 + 旧 settings）迁移后：folder 实例仍按原 inbox/outbox 工作、历史工单可打开、GitHub 实例仍轮询原仓库；多实例并行且互不串数据。

## 9. 实施结果（`9d3ac6d`，2026-11-25）

- `pnpm check` exit 0：61 文件、**1208 passed / 14 skipped（1222）**；工作树干净。
- 实例身份：`instanceId = <kind>:<key>`，旧数据保留 bare kind；`kindOf`/`instanceFor`（用旧 folder `meta.row`/`address.row` 提示找实例，保证旧 Trigger/Channel/Mandate 可解析）。
- **Thread 键无缝**：新 `{source:'folder:ops', id:'demo-1.md'}` 与旧 `{source:'folder', id:'ops:demo-1.md'}` 都得到 `folder:ops:demo-1.md`；github/feishu 实例 id=kind 时旧键不变，具名 github 实例为 `github:<repo>:<n>`。
- 迁移：`settingsAsInstances` + `migrateSettingsToInstances`，folder `folders[]` 每行拆实例、policy 键与 admission row 跟随、folder 游标搬到实例 id（不重复摄入旧投件）、写 `origin='migration'` 设置 revision；旧 folder policy part 保留以兼容旧 Mandate。
- 面板/视图最小适配（仅随数据形状调整，无新页面）。
- 遗留（转 P3/P4）：
  1. Setup 仍按 bare kind 读 github/feishu 配置；具名 GitHub 实例不参与启动校验、改 CLI 不触发账号检查（P3 建源流程一起做）。
  2. 无「添加来源」API/UI 与实例 key 归一化入口（P3）。
  3. 历史 settings 快照不回写新结构；个别旧快照 diff 显示 `changes: null`。
  4. 旧 folder Trigger 的 `source` 仍是 bare `folder`，24h 统计按实例 id 聚合时不回填到具名卡（P3 页面处理）。
  5. 具名 github 实例的 assessment 仓库资源读取仍用 deployment 仓库（P3 统一读取路径）。
