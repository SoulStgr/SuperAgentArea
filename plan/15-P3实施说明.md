## 1. 数据与统计口径（后端）

每实例（SourceInstance）需要：

| 字段 | 口径 | 现有/新增 |
|---|---|---|
| `state` | 现 `sourceState`（missing/off/error/setup/starting/paused/ready） | 已有 |
| `health` | **kind 级**（P1b 决定；实例级留 P6），detail 可含实例汇总 | 已有 |
| `pending` | 该实例**未结束**工单数（`liveTicket`） | 新增（按 `ticket.sourceId` 计数） |
| `stats24h` | 到达 / 被过滤 / 已评估 / 接单或忽略 | 扩展（见下） |
| `exec` | 该实例工单的 **执行中 / 排队 / 等待触发** | 新增 |
| `pendingProjects` | 该实例下 `needsProject` 未回答的触发（P2 已有字段，补实例过滤正确性） | 已有 |
| `recent` | 最近投件/触发（可选，卡片下或详情） | 新增 |

**计数实现要求**：
- `triggerStats` 目前按 `json_extract(value,'$.source')` 分组（`src/app/store-read.ts:12-17`）。**旧 trigger 的 source 是 bare kind**，新的是实例 id。扩展为按 `(source, meta.row)` 分组：folder 旧触发用 `meta.row` 映射到 `folder:<row>`；github/feishu 旧触发映射到默认实例（id=kind）。聚合时用 `SourceRegistry.instanceFor(source, row)`。
- 「已评估 / 接单或忽略」：沿用 `flow` 的思路（decision.triggerIds → trigger），但按实例分组；「已评估」= 24h 内到达且有过 decision 的 trigger 数；「接单或忽略」= 其中 accept/reopen/ignore 的数量（与现有 overview 口径一致，避免两处数字打架）。
- `exec`：用 `ticketStage`：
  - 执行中 = stage `working`（或 runningAssignment 存在）；
  - 排队 = 已接受但未开始（`waiting`/有 assignment 未 started）；
  - 等待触发 = `waiting` 阶段中等待 follow-up/停止后恢复的；实现时以现有 stage 表为准，测试锁定口径。
- `tickets?source=` 过滤：`GET /tickets` 增 `source` 参数；旧 bare kind 参数映射到默认实例；`ticketList` 增过滤参数或新增 `ticketListBySource`。

## 2. API

```
GET  /sources                     → 每实例：{id, kind, label, enabled, state, health, pending, stats24h{arrived,filtered,judged,accepted}, exec{working,queued,waiting}, pendingProjects[], recent[]}
GET  /sources/:id                 → 实例详情：上述 + {fields, value{enabled,config}, tickets(摘要/分页), filtered[], dropped[], defaults}
POST /sources                     → { kind, key?, label?, config } 新建实例；key 归一化（小写/非字母数字→-）、查重、kind 必须已注册
PATCH /sources/:id                → { enabled?, label?, config?, defaultProjectId? }；config 用 kind.schema 校验；账号类字段仍限面板来源
GET  /tickets?source=<instanceId>&state=...   → 该源工单
POST /triggers/:id/answer-project  （P2 已有；P3 前端接线）
```

- **设置块 id**：`PUT settings/source:<instanceId>` 目前被 `SettingsBlockSchema` 的 `source:` 后正则（`^[a-z][a-z0-9-]*$`，`src/app/http.ts`）拒绝冒号。P3 放开为 `<kind>(:<key>)?`，并同步 `Settings` 的 known 检查（`sources.instances()` 按实例 id）。
- 新建实例后：启用状态默认 true；`restarts` 规则沿用 kind 的 `SETUP_FIELDS`（账号类变更需 restart）；folder 实例无需 restart。
- **不新增「删除来源」**：先支持禁用（enabled=false）；删除留 P4/P6（涉及历史工单归属）。

## 3. 页面（客户端）

路由：沿用 `{page:'source'}` 作为「工单源」；详情 `{page:'source', id: instanceId}`（保持现有路由模型，深链仍不做）。

- **列表页**：
  - 每实例一张卡（响应式网格 ≥2 列）：
    - 头部：状态点 + 标题（label 或 `kind · key`）+ 启用开关；
    - **待处理工单 N**；0 时显示「没有待处理的工单」；
    - **过去 24 小时**：到达 / 被过滤 / 已评估 / 接单或忽略；
    - **执行状态**：执行中 / 排队 / 等待触发；
    - 未归属问题：有 `pendingProjects` 时显示一行提示（点击打开回答对话框）；
  - 页头动作：**添加来源**（选择 kind → 表单：key/label + kind 配置字段）；
  - 空态：没有来源时引导「添加第一个来源」。
- **详情页**：实例配置表单（沿用 `settings-kit` 的字段渲染，folder 为 inbox/outbox/operator/pollSeconds）、24h 统计、该源工单列表（分页）、被过滤/未发送折叠列表、最近投件、未归属问题回答区。
- **回答对话框**（最小实现）：三选一——归到已有工作站（候选下拉）/ 确认 agent 提案（若存在）/ 新建工作站（名称 + 本地目录或仓库地址）→ `POST /triggers/:id/answer-project` → 成功提示 + 刷新。
- **复用**：`TicketLine`、`Pill`、`Button/Input/Modal`、`settings-kit` 字段渲染；不引入新依赖；客户端的「零运行时 DSH 导入」约束不变（`tests/controls.spec.tsx`）。

## 6. 验收

`pnpm check` exit 0；用真实（或测试夹具）实例验证：
1. 两个 folder 实例 + 一个 github 实例各自一张卡，统计互不串；

4. 旧数据（bare kind 触发/工单）仍计入对应默认实例的卡片。
